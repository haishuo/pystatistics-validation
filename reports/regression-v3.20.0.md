# Validation report — pystatistics `regression` v3.20.0

> This report validates **pystatistics regression v3.20.0**, installed from **pypi**. Evidence lives in `artifacts/regression/v3.20.0/`. It was generated by `render_report.py` from frozen artifacts — **do not edit numbers by hand**; fix the artifact or the renderer and re-render.

**Subsystem:** Linear and generalized linear models (OLS + GLM families) (`pystatistics.regression`)

## 1. What statistical procedure is implemented?

Ordinary least squares and the generalized linear model under one interface. OLS estimates the coefficient vector beta minimizing the residual sum of squares for a Gaussian-error linear model, reporting standard errors, t-statistics, p-values, R-squared and the residual standard error. The GLM extends this to non-Gaussian responses (binomial, Poisson, Gamma, negative binomial) via a link function, estimating beta by maximum likelihood and reporting standard errors, Wald z/t-statistics, p-values, deviance and AIC. pystatistics deliberately unifies lm and glm — which R splits across lm() and glm() — into a single fit(design, family=...) entry point.

## 2. Which algorithms are used?

- OLS, CPU (reference path): column-pivoted QR decomposition of the design matrix (the same factorization R's lm() uses), so coefficients, rank detection and the residual statistics match R to floating-point round-off. fp64, deterministic.
- OLS, GPU: Cholesky factorization of the normal equations (X'X) beta = X'y, fp32 by default on consumer GPUs. Faster than QR for well-conditioned designs but squares the condition number; the backend computes the design's condition number and refuses the Cholesky path (unless force=True) when it exceeds 1e6, falling back to a least-squares solve.
- GLM (all families): Iteratively Reweighted Least Squares (IRLS / Fisher scoring) to the maximum-likelihood coefficients, with R's glm.control defaults (tol 1e-8, max 25 iterations). Standard errors come from the inverse Fisher information at the solution.
- GLM, GPU: each IRLS step solves the weighted normal equations (XtWX) beta = XtWz by Cholesky (a Metal-supported primitive, so GLM runs on Apple Silicon as well as CUDA). fp32 by default. When the float32 fit cannot converge (log-link families at large n, where XtWX is ill-conditioned in fp32) it FAILS LOUD with a NumericalError listing the options (CPU, a ridge-penalized fit, or force=True), rather than returning unreliable coefficients.
- Ridge (L2-penalized) regression: predictors standardized, intercept unpenalized, penalty l2 added on the standardized scale (matching MASS::lm.ridge / glmnet alpha=0). On the GPU the penalty conditions XtWX so the float32 Cholesky is stable — a ridge GLM fits fast and stably on the GPU at large scale where the plain GLM cannot. Penalized fits do not report standard errors (a biased estimator has no valid frequentist inference).
- Negative binomial: the dispersion parameter theta is estimated by profiling — alternating an IRLS fit of beta at fixed theta with a maximum-likelihood update of theta — mirroring MASS::glm.nb.
- Backends, named as backend='<device>[_<precision>]': cpu (fp64, the R-reference path); gpu (fp32, the speed path — MPS on Apple Silicon, CUDA on NVIDIA); gpu_fp64 (fp64, CUDA-only, a numerically-exact correctness path — Metal has no fp64 and raises a clear error).

## 3. How does it compare to R stats::lm / stats::glm / MASS::glm.nb?

R's lm() (OLS via pivoted QR) and glm() (GLM via IRLS) are the established reference implementations; the negative-binomial reference is MASS::glm.nb. Because pystatistics merges lm and glm into one module, the head-to-head pulls from BOTH R functions: lm() for the OLS claim and glm()/glm.nb() for the GLM-family claims. Agreement in coefficients, standard errors, test statistics, p-values, and the model-level fit summary (R-squared for OLS, deviance for GLM) is the correctness claim.

## 4. What numerical tolerances are expected?

- **ols_vs_r:** CPU OLS agrees with R lm() to fp64 round-off (coefficients and standard errors to ~1e-12 relative or better) because both use pivoted QR on the same design.
- **glm_vs_r:** CPU GLM coefficients agree with R glm() to IRLS-convergence round-off (~1e-10 relative for binomial/Poisson). Standard errors and Wald statistics follow the coefficients.
- **gamma_link:** The Gamma claim is specifically for the LOG link (the textbook positive-continuous target). pystatistics' family='gamma' string defaults to the canonical INVERSE link; the validation pins GammaFamily(link='log') to match the reference. Gamma standard errors differ from R at the ~1e-2 relative level because pystatistics estimates the dispersion by maximum likelihood while R uses the Pearson/df estimator — a documented, intentional difference, not a defect.
- **negbin:** Negative-binomial coefficients agree with MASS::glm.nb to ~1e-4 relative; the small gap is the profiled theta landing at a slightly different value. The NB mean structure is identified only up to theta, so coefficient agreement on real overdispersed counts is the practical claim.
- **gpu_fp32:** GPU paths are fp32 by default and agree with the CPU/R reference to ~1e-4 relative on coefficients (float32 tier).
- **gpu_fp64:** backend='gpu_fp64' (CUDA only) agrees with the CPU reference to ~1e-15 — numerically exact; a correctness option, not a speed claim (fast double precision needs a data-center GPU).
- **ridge_vs_r:** Ridge coefficients match MASS::lm.ridge to ~1e-15 (LM) and glmnet(alpha=0) (GLM) at matched lambda. A ridge GPU fit matches the CPU ridge fit to the float32 tier (~1e-4).

## 6. What are the known limitations?

- GPU OLS uses Cholesky on the normal equations, which squares the condition number; ill-conditioned designs (condition number > 1e6) are refused unless force=True. Use the CPU QR backend for ill-conditioned problems.
- Plain (unpenalized) GLM with a log link (Poisson/Gamma) is ill-conditioned in float32 at large sample size and does not converge on the GPU there — the fit FAILS LOUD rather than returning wrong numbers. The remedies are backend='cpu' (exact, slower), a ridge-penalized GPU fit (fast and stable — the penalty fixes the conditioning), or backend='gpu_fp64' on CUDA (exact). Binomial (bounded) is float32-stable and is unaffected.
- GPU fp32 is the speed path; for double precision use backend='cpu' anywhere, or backend='gpu_fp64' on CUDA. Apple Silicon (Metal/MPS) has no float64 at all, so gpu_fp64 is CUDA-only.
- The negative-binomial solution object does not expose the auto-estimated theta, so the NB validation compares coefficients (and SEs) rather than theta directly.
- Tiny designs (n in the low hundreds) are dominated by fixed Python dispatch overhead and sit near R's timer resolution; the scaling study, not the small real datasets, carries the rigorous speed claim.
