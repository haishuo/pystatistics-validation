# Validation report — pystatistics `mixed` v4.5.6

> This report validates **pystatistics mixed v4.5.6**, installed from **pypi**. Evidence lives in `artifacts/mixed/v4.5.6/`. It was generated by `render_report.py` from frozen artifacts — **do not edit numbers by hand**; fix the artifact or the renderer and re-render.

**Subsystem:** Mixed models — linear (LMM), generalized-linear (GLMM), and a low-rank / GRM mixed model (`pystatistics.mixed`)

## 1. What statistical procedure is implemented?

Linear mixed models under one module. lmm() fits a linear mixed model y = Xβ + Zb + ε with fixed effects β and Gaussian random effects b (random intercepts and/or slopes, over one or more crossed or nested grouping factors), estimating the variance components by REML (default) or ML via the profiled deviance of Bates et al. (2015), and reporting the fixed-effect table (coefficients, standard errors, Satterthwaite denominator df, t- and p-values), the random-effect variance components (variances, correlations, and the residual variance), the log-likelihood / REML criterion and AIC/BIC, and the conditional modes (BLUPs) of the random effects. grm_lmm() is a separate, GPU-capable low-rank / GRM mixed model: a linear mixed model with a single low-rank variance component K = W Wᵀ / M (e.g. a genomic relatedness matrix from M standardized markers), reporting the fixed-effect table, the genetic and residual variance components, narrow-sense heritability h² = σ²_g/(σ²_g + σ²_e), and genetic-value BLUPs. pystatistics matches R lme4::lmer / lmerTest::lmer (LMM) and rrBLUP::mixed.solve (GRM). glmm() fits a generalized linear mixed model by the Laplace approximation (equivalent to lme4::glmer with nAGQ=1): a penalized IRLS inner loop finds the conditional modes of the random effects while the fixed effects and the variance components are optimized together over the Laplace-approximated deviance, reporting the fixed-effect table (coefficients, standard errors, Wald z, p-values), the random-effect variance components, the conditional modes (BLUPs), the log-likelihood / deviance and AIC/BIC, for the binomial and Poisson families (logit/probit and log links). pystatistics matches R lme4::lmer / lmerTest::lmer (LMM), lme4::glmer (GLMM, Laplace nAGQ=1), and rrBLUP::mixed.solve (GRM).

## 2. Which algorithms are used?

- LMM, CPU (the R-reference path, fp64): the profiled REML/ML deviance (Bates et al. 2015) is minimized over the relative random-effects covariance parameters θ (the Cholesky factor of the RE covariance relative to σ²). The penalized-least-squares (PLS) system is solved WITHOUT materializing the dense random-effects design: a single grouping factor uses a batched per-group dense Cholesky of the block-diagonal system, and crossed / nested designs use a sparse Cholesky with a fill-reducing ordering (scipy splu, MMD_AT_PLUS_A). Fixed-effect standard errors come from the p×p Schur factor RX already produced by the solve — Var(β̂) = σ²·(RX·RXᵀ)⁻¹ — an O(p³) computation (not a dense n×n V⁻¹). Denominator degrees of freedom use the Satterthwaite approximation. CPU-only: the general LMM/GLMM deliberately has no GPU backend (a documented decision matching lme4, MixedModels.jl, and glmmTMB — the sparse-Cholesky regime does not earn a GPU path; see the GPU investigation).
- LMM θ-optimization: L-BFGS-B from a multi-start over θ (the primary path). A bounded derivative-free Nelder-Mead fallback (bobyqa-analogue) is engaged only when L-BFGS-B does not converge OR a cheap scale-aware stationarity probe flags a premature stop, and its result is adopted only when it strictly lowers the deviance — so well-converged fits are byte-for-behaviour unchanged, while the extreme variance-ratio regime (ICC→1, where the optimal θ is very large and the gradient-based line search fails or stops early) converges to the true optimum (the 4.5.1 fix for finding F3).
- LMM singular-fit detection (mirrors lme4 isSingular): after the fit, a random-effects variance collapsed to ~0 or an implied intercept/slope correlation driven to ±1 is flagged via LMMSolution.is_singular and a RuntimeWarning — the boundary MLE is still returned (matching lme4's numbers), but the user is told the fit is on the boundary.
- GRM / low-rank model, CPU (fp64 reference): the profiled REML/ML deviance is evaluated in the low-rank M-space via the Woodbury identity (an M×M dense Cholesky + n×M GEMMs rather than an n×n solve) and minimized over the single variance ratio by a 1-D search. Reports β (SE via the p×p Schur form), σ²_g, σ²_e, heritability, and genetic-value BLUPs (GRMSolution).
- GRM GPU backends, named as backend='<device>[_<precision>]': cpu (fp64), gpu (fp32 — the dense M×M Gram + GEMMs are the cuBLAS/cuSOLVER regime), gpu_fp64 (fp64, CUDA-only), auto. The fp32 GPU path forms the Gram K = W Wᵀ / M in single precision (the CF-1 exposure), so it checks the conditioning of W in DOUBLE precision and REFUSES loudly (core.exceptions.NumericalError) on designs past the fp32-safe boundary rather than returning a biased fit; force=True is the documented override. lmm()/glmm() expose no backend= — grm_lmm() is the only GPU-capable model in mixed, and is never described as 'LMM on GPU'.
- GLMM, CPU (Laplace / nAGQ=1, fp64): the marginal likelihood is approximated by Laplace's method. For fixed variance parameters θ, a penalized IRLS (PIRLS) inner loop finds the conditional modes û of the random effects; the fixed effects β are NOT solved inside PIRLS but optimized in the OUTER loop together with θ over the Laplace deviance d(θ,β) = deviance(y,μ̂) + ‖û‖² + log|Λ'Z'WZΛ+I| — this is what makes glmm match glmer's default (nAGQ=1) rather than the cruder nAGQ=0 scheme. The outer optimization is L-BFGS-B seeded by an nAGQ=0 warm start, with a bounded derivative-free (Nelder-Mead) fallback engaged when L-BFGS-B stops at a non-stationary/boundary point and adopted only if it strictly lowers the deviance (so well-converged fits are unchanged). The inner PIRLS solves through the same structure-exploiting weighted factor as the LMM (batched per-group for a single grouping factor; sparse Cholesky for crossed/nested) — near-linear in the number of groups, not dense O(#groups³) — and step-halves with an η clamp so a non-canonical link (Poisson log) cannot overflow on a far-from-optimum probe. Fixed-effect SEs are the inverse of the p×p Schur complement of the penalized system at the mode (σ²=1 by convention). CPU-only: no backend= (a documented decision matching lme4/glmmTMB). Free-dispersion families (gaussian, gamma) are refused loudly.

## 3. How does it compare to R lme4::lmer / lmerTest::lmer (LMM) + lme4::glmer (GLMM, Laplace nAGQ=1) + rrBLUP::mixed.solve (GRM)?

lme4::lmer is the LMM reference for the point estimates, standard errors, variance components, log-likelihood and BLUPs; lmerTest::lmer supplies the Satterthwaite denominator df and p-values that lme4 deliberately omits. rrBLUP::mixed.solve (GBLUP/GRM; called with the GRM K = W Wᵀ / M and Z = I so the random effects are per-individual genetic values) is the reference for grm_lmm. Agreement is measured on the fixed effects, the variance components, and the BLUPs. Two honest tolerance tiers are reported for the LMM: fixed-effect coefficients are pinned near machine precision, while the variance components / SEs / df / BLUPs are bounded by the variance-parameter optimizer tolerance (lme4's bobyqa vs pystatistics' L-BFGS-B), a contract stated rather than a defect. Log-likelihood values are NOT compared across engines for the GRM (rrBLUP's restricted likelihood uses a different additive constant; every estimate agrees regardless). For the GLMM, lme4::glmer with nAGQ=1 is the Laplace reference (matching glmm's approximation order); agreement is a two-tier contract like the LMM (near-tight fixed effects + logLik/deviance/AIC/BIC; optimizer/Laplace-tier SEs, variance components and BLUPs).

## 4. What numerical tolerances are expected?

- **lmm_fixed_effects_tight:** Fixed-effect coefficients β agree with lme4 to ~1e-16..3e-13 relative across sleepstudy (random slopes + correlation), Penicillin (crossed), Dyestuff (simple), Dyestuff2 (singular) and Pastes (nested), under both REML and ML — near machine precision, because conditional on the converged θ, β is a linear GLS solve and the two optimizers land θ closely.
- **lmm_loglik_tier:** The log-likelihood / REML criterion / AIC / BIC agree to ~1e-11 relative. These are technically optimizer-bound (bobyqa vs L-BFGS-B converge θ to a finite tolerance) but far tighter than the variance components because the profiled likelihood is flat near its optimum.
- **lmm_variance_components_optimizer_tier:** Variance components, their derived standard errors, Satterthwaite df, p-values and BLUPs agree to ≤ ~1.3e-4 (optimizer tier). This is the honest promised bound: lme4's derivative-free bobyqa and pystatistics' L-BFGS-B stop the variance-parameter search at a finite tolerance, so agreement here is optimizer-bound, not machine-precision. Random-effect correlations are the loosest sub-tier.
- **lmm_hardcases_r10:** On the adversarial grid pystatistics matches R's BEHAVIOUR, not only easy-data numbers (RIGOR R10). Singular fits: Dyestuff2 (a between-group variance to the boundary → 0) and a constructed perfect intercept/slope correlation (the 2×2 RE covariance to rank-deficient) are both flagged is_singular=True with the boundary RuntimeWarning, matching lme4's isSingular() and its 'boundary (singular) fit' message, while the boundary MLE matches R. Unbalanced groups with singletons, extreme variance ratio (ICC≈0.99999 — converges and matches R to 6.9e-6 on the variance component after the 4.5.1 F3 fix), and nested-via-interaction (matches lme4's nested fit to machine precision) all hold. The reused-inner-label footgun is a MATCHED behaviour (pystatistics and lme4 both treat reused inner labels as crossed) — a documented usage caveat, not a deviation.
- **lmm_default_invocation_r15:** The bare lmm(y, X, groups=...) a naive user writes (random_effects=None → a random intercept per group, REML, default optimizer) is identical to the explicit (1|group) spec (0.0 difference) and matches lme4's default lmer to ~3e-16.
- **lmm_cpu_speed_r1:** CPU speed is a first-class deliverable (RIGOR priority 3 / R1). Random-intercept models: pystatistics MEETS-OR-BEATS lme4 at every size (3.2–5.3× faster) across the group-count sweep (G = 10 … 2000, n up to 16000), with near-linear empirical complexity (~O(n^0.45) vs lmer ~O(n^0.39)) — the structure-exploiting solver (4.5.0) removed the earlier dense-design O(n^1.4) gap and the O(n³) standard-error cost. Random-slope (correlated 2×2 RE) models are competitive at small sizes and ~2× slower than lmerTest at scale (finding F4): ~26% of the gap is the Satterthwaite df pystatistics computes in-fit that lmerTest defers (an R2 cost), the rest is the correlated-RE deviance/optimizer; a documented cost with an autodiff-gradient optimization on the roadmap, not a complexity-class gap.
- **lmm_no_gpu_path:** The general LMM/GLMM is CPU-only by design — no backend= is exposed. A dedicated GPU investigation (turning over batched per-group Cholesky, CG/Woodbury, autodiff, and GLMM PIRLS) found no formulation of the general lme4-style sparse-Cholesky mixed model that beats the fp64 CPU, matching all prior art (lme4, MixedModels.jl, glmmTMB stay CPU). The one GPU-warranted formulation is a DIFFERENT model — the low-rank / GRM model below — shipped separately and honestly as grm_lmm().
- **grm_cpu_vs_rrblup:** grm_lmm(backend='cpu') agrees with R rrBLUP::mixed.solve across heritabilities h² ∈ {0.2, 0.5, 0.8} and sizes (n=400/M=80, n=800/M=150): fixed effects β ≤ 3.4e-7, β SEs matched, genetic variance σ²_g ≤ 2.0e-5, residual variance σ²_e ≤ 4.8e-6, heritability ≤ 9.3e-6, and genetic-value BLUPs to a correlation of exactly 1.000000 (max-scaled ≤ ~3e-5) — all optimizer-tier or tighter. Log-likelihood is not compared across engines (rrBLUP's restricted likelihood uses a different additive constant; the estimates agree regardless).
- **grm_gpu_cf1_no_silent_wrong_r12:** The fp32 GPU Gram path is the CF-1 exposure (an fp32 K = W Wᵀ / M). Sweeping cond(W) across the fp32 boundary on BOTH MPS and CUDA, silent_wrong_count = 0: every ACCEPTED fp32 fit is correct vs the fp64 CPU optimum (|Δh²| ≤ ~2.3e-3, the fp32 statistical-equivalence tier), and every design past the fp32-safe boundary (cond(W) ≳ 1e4) REFUSES loudly (NumericalError), with force=True the documented override. The gate is a true classifier in both directions — never accepts a biased fit (R12), never refuses a recoverable one (R9) — and behaves identically on MPS and CUDA (R13 re-proven on each). The gate keys on the DOUBLE-precision conditioning of W, so it survives a torch upgrade (R14).
- **grm_gpu_earns_its_keep_r11:** grm_lmm's GPU path earns its place on CUDA (RIGOR priority 4): fp32 is 6.6× (n=5000) and 14.7× (n=20000) faster than the fp64 CPU, with accepted fits correct to |Δh²| ≤ 2.1e-4. The R11 same-precision pivot gpu_fp64 vs cpu_fp64 isolates the hardware effect: gpu_fp64 is numerically EXACT vs CPU (|Δh²| ≤ 1.8e-8) but only 1.2–1.6× faster (the consumer RTX 5070 Ti runs fp64 far below fp32 throughput) — a correctness option, so the fp32 headline is precision + hardware, reported honestly. MPS is a correctness / portability path only: the CF-1 gate holds (silent_wrong=0) but it does NOT beat the CPU on speed (0.27–0.74×) — stated plainly, not dressed as a win. The GPU speed story is CUDA.
- **version_sensitivity_r14:** GPU paths validated on torch 2.12.1 (Apple Silicon / MPS) and torch 2.11.0.dev+cu128 (NVIDIA RTX 5070 Ti / CUDA, compute capability 12.0). The version-INDEPENDENT guarantee is the host-double-precision conditioning gate on the GRM fp32 path: it keeps an fp32-unrecoverable Gram loud regardless of the torch build. The fp64 CPU path is the version-independent correctness anchor. R side: lme4 1.1.38, lmerTest 3.2.0, rrBLUP 4.6.3; numpy and R both link Apple Accelerate BLAS on the CPU host.
- **glmm_fixed_effects_and_fit_tight:** GLMM (vs glmer nAGQ=1): fixed-effect coefficients and the log-likelihood / conditional deviance / AIC / BIC agree to ~1e-3 relative or better across binomial/logit (cbpp), poisson/log (grouseticks), a correlated random slope (glmm_slope_synth) and a probit link (cbpp_probit). Conditional on the converged (θ,β) the fixed effects are pinned by the Laplace objective both engines optimize.
- **glmm_optimizer_laplace_tier:** GLMM variance components, their derived standard errors, Wald z, p-values and BLUPs agree with glmer to ~1-2% (optimizer + Laplace-mode tier): both optimizers stop the variance-parameter search at a finite tolerance and the fixed-effect covariance is the Schur inverse evaluated at the conditional mode — bounded, stated, not machine-precision.
- **glmm_hardcases_r10_r15_a6:** On the adversarial grid glmm matches glmer's BEHAVIOUR: quasi-separation (huge-but-finite slope, ~4e-5), a singular random effect (variance collapses to 0, matching glmer isSingular — though glmm exposes no is_singular flag, finding G6), and unbalanced/singleton groups (~2e-4). R15: the bare default glmm(y,X,groups,family='binomial') equals the explicit (1|group) spec (0.0) and matches glmer's default. A6: gaussian/gamma families fail loud (ValidationError) rather than returning silently-wrong fit statistics.
- **glmm_cpu_speed_r1:** GLMM CPU speed (priority 3 / R1): after the 4.5.5 structure-exploiting solver there is NO complexity-class gap vs glmer — empirical exponent ~O(n^0.48) for pystatistics vs ~O(n^0.69) for glmer on a binomial random-intercept group-count sweep. A residual constant factor (speedup 0.33x at G=10 rising to 0.63x at G=400/n=6000) is the price of computing more per fit than glmer defers: the two-stage nAGQ=0→nAGQ=1 Laplace, the in-fit fixed-effect SEs, and the robustness stationarity probe — a documented R2 cost, not a scaling defect.
- **glmm_no_gpu_path:** Like lmm(), glmm() exposes no backend= — the general GLMM is CPU-only by design (the sparse-Cholesky/PIRLS regime does not earn a GPU path; matching lme4/glmmTMB). GPU acceleration in mixed lives only in grm_lmm().

## Constitutional compliance & GPU backend reconciliation

R4 constitutional-compliance note for the mixed public surface (lmm, glmm, grm_lmm, LMMSolution, GLMMSolution, GRMSolution). All selectors and error types conform to CONVENTIONS.md: grm_lmm uses the backend='<device>[_<precision>]' device+precision encoding (cpu/gpu/gpu_fp64/auto — no use_fp64), and an unknown backend fails loud with core.exceptions.ValidationError; the fp32-Gram conditioning refusal raises core.exceptions.NumericalError. LMMSolution.is_singular is a plain bool accessor; GRMSolution uses z_values (Wald z) not t_values, appropriate for its normal-approximation inference (Amendment A3). GLMM: GLMMSolution uses z_values (Wald z) not t_values (Amendment A3, normal-approximation inference); family/link resolve via core families; free-dispersion families and unknown selectors fail loud with core.exceptions. glmm() exposes no backend= (CPU-only, like lmm()). No selector/deviations found.

**GPU backend reconciliation.** lmm() and glmm() expose NO backend= — the general mixed model is CPU-only, a deliberate, documented decision (the sparse-Cholesky regime does not earn a GPU path; confirmed by a dedicated GPU investigation and matching lme4/MixedModels.jl/glmmTMB). grm_lmm() is the only GPU-capable model in the module and is scoped/named as a low-rank / GRM model for the genomics audience, never as 'LMM on GPU'. Its fp32 GPU path is gated loud by the CF-1 double-precision conditioning check.

**Findings:**

- **F1 — no singular-fit diagnostic** _(RESOLVED at 4.5.0)_: 4.4.1 returned singular/boundary fits silently (converged=True, no signal). 4.5.0 added LMMSolution.is_singular + a boundary RuntimeWarning mirroring lme4 isSingular; validated on Dyestuff2 (scalar boundary) and the perfect-correlation 2×2 boundary.
- **F2a — O(n³) fixed-effect standard errors** _(RESOLVED at 4.5.0)_: The LMM SE formed a dense n×n V⁻¹ (~83% of lmm() runtime). Replaced by the p×p Schur form Var(β̂)=σ²·(RX·RXᵀ)⁻¹ — machine-identical to the prior result, several orders of magnitude faster.
- **F2b — dense random-effects design → complexity-class CPU gap** _(RESOLVED at 4.5.0)_: The dense Z + dense PLS was ~O(n^1.4) and OOM'd at scale. The structure-exploiting solver (batched per-group Cholesky for a single factor; sparse Cholesky for crossed/nested, scipy-only, no new dependency) makes random-intercept fits near-linear and faster than lme4 (a 2000-group fit ~197 s → ~0.05 s); crossed designs that ran out of memory now fit.
- **F3 — extreme variance-ratio non-convergence (and a silent-wrong sibling)** _(RESOLVED at 4.5.1)_: At ICC→1 the 4.5.0 L-BFGS-B θ-optimizer failed its line search (converged=False, ~17% biased variance) or, at a slightly more extreme ratio, stopped early at a non-stationary point (silently wrong). A bounded derivative-free Nelder-Mead fallback (engaged only on non-convergence / a stationarity-probe flag, adopted only if it strictly lowers the deviance) fixes both; validated against live lme4 across a residual-sd × seed sweep (0 non-convergences, variance components to ≤ 8e-4). Well-converged fits are byte-identical.
- **F4 — multi-term RE ~2× slower than lmerTest at scale** _(DOCUMENTED (R2) + roadmap)_: A constant-factor gap (not complexity-class); ~26% is in-fit Satterthwaite df (which lmerTest defers), the rest the correlated-RE optimizer. Autodiff θ-gradient is the roadmap fix. Correctness unaffected.
- **G1 — glmm was nAGQ=0, not the documented Laplace (nAGQ=1)** _(RESOLVED at 4.5.2)_: glmm optimized only θ with β solved inside PIRLS (nAGQ=0), so fixed effects matched glmer(nAGQ=0) and differed from the default glmer(nAGQ=1) by several percent while the docstring claimed 'Laplace'. Fixed: β moved into the outer optimization over the Laplace deviance; now matches glmer(nAGQ=1) to ~1e-3.
- **G2 — silently-wrong fixed-effect SE for correlated predictors** _(RESOLVED at 4.5.2)_: _compute_se_glmm used (RXᵀRX)⁻¹ instead of the correct (RX·RXᵀ)⁻¹ Schur inverse — right only for orthogonal designs; a correlated-predictor slope SE came out ~8x too small (wrong z/p/CIs). Corrected to the Schur inverse at the mode; matches glmer to ~1-2%. Regression test added.
- **G3 — free-dispersion families returned silently-wrong statistics** _(RESOLVED at 4.5.3)_: glmm(family='gaussian'|'gamma') fixed dispersion at 1, giving a nonsensical logLik/AIC/variance (e.g. gaussian logLik -77577 vs -897) while coefficients looked fine. Now raises ValidationError, directing gaussian users to lmm().
- **G4 — Poisson PIRLS overflow + silent variance-collapse** _(RESOLVED at 4.5.4, completed at 4.5.6)_: The Laplace inner PIRLS overflowed (exp(η)→∞) on far-from-optimum Poisson probes (grouseticks crashed), and the outer L-BFGS-B could overshoot an interior variance optimum to the θ=0 boundary and report converged=True at a worse fit (probit: variance≈0 vs 0.11). Fixed with η-clamped step-halving and a derivative-free outer fallback adopted only if it strictly lowers the deviance. Completed at 4.5.6: a fit sitting on the variance lower bound is treated as always-suspect and re-optimized by a derivative-free search from the original start (adopted only if it strictly lowers the deviance), fixing a residual collapse on flat deviance surfaces — including a default-invocation (R15) binomial fit where glmer finds variance ~0.17; genuine singular fits still return 0 (a true classifier, variance within ~1e-3 of glmer).
- **G5 — dense O(#groups³) Laplace PIRLS — complexity-class scaling gap** _(RESOLVED at 4.5.5)_: The GLMM PIRLS built a dense random-effects design and factored a dense q×q system, so cost grew ~O(#groups³) and a 400-group binomial fit was ~6.6x slower than glmer and widened with size. Replaced with the structure-exploiting batched/sparse weighted factor (the LMM solver, extended with IRLS weights); estimates unchanged, scaling now near-linear (no complexity-class gap).
- **G6 — no singular-fit diagnostic for glmm** _(DOCUMENTED (gathered, R18))_: When a random-effect variance collapses to the boundary glmm returns the correct boundary MLE (matching glmer's numbers) but exposes no is_singular flag / boundary warning as lmm() does. Behaviour-correct, diagnostic-absent; logged as a limitation, not a silent-wrong.
- **G7 — no aggregated-binomial / prior-weights / offset support** _(DOCUMENTED (scope))_: glmm takes a single response vector with unit weights — no cbind(successes, failures) response, prior weights or offset. A scope limitation (use an expanded Bernoulli representation, as the cbpp validation dataset does); not a correctness defect.

## 6. What are the known limitations?

- Random-slope (multi-term, correlated random-effects) LMMs are ~2× slower than lmerTest at scale (finding F4): competitive at small group counts, 0.41× at G=2000/n=16000. About a quarter of the gap is the Satterthwaite df pystatistics computes during the fit that lmerTest computes lazily (an R2 cost — pystatistics returns more); the remainder is the correlated-RE deviance/optimizer. Correctness is unaffected; an autodiff θ-gradient (fewer deviance evaluations) is the roadmap optimization. Random-intercept models beat lme4 at every size.
- The extreme variance-ratio convergence issue (finding F3 — ICC→1, residual variance orders of magnitude below the RE variance) is FIXED at 4.5.1 via the derivative-free optimizer fallback; it was present in 4.5.0 (which failed loud with converged=False). Extremely ill-scaled designs still rely on that fallback path rather than the primary L-BFGS-B.
- grm_lmm on MPS (Apple Silicon) is a correctness / portability path, NOT a speed one: the CF-1 gate holds and accepted fits are correct, but it does not beat the fp64 CPU (0.27–0.74×). The GPU speedup is CUDA-only. gpu_fp64 on a consumer NVIDIA card is numerically exact but only modestly faster than the CPU (fp64 throughput is far below fp32) — a correctness option, not the speed path (which is fp32).
- The general lmm()/glmm() have no GPU backend by design (documented decision, matching lme4/MixedModels.jl/glmmTMB). GPU acceleration in mixed lives only in the separate low-rank grm_lmm() model, which never claims to be 'LMM on GPU'.
- An autodiff θ-gradient (TMB-style, ~7× fewer deviance evaluations) is a roadmap optimization, deferred pending a library-wide torch-dependency-tier decision (it would pull torch onto the core CPU path).
- glmm() is ~1.5-3x slower than lme4::glmer at these sizes (a constant factor, NOT a complexity-class gap after 4.5.5): it computes the fixed-effect SEs in-fit, runs a two-stage nAGQ=0→nAGQ=1 Laplace optimization, and pays a derivative-free robustness probe that glmer does not — a documented R2 cost. Empirical scaling matches glmer.
- glmm() supports the binomial and Poisson families (logit/probit and log links). Free-dispersion families (gaussian, gamma) are refused loudly (dispersion is fixed at 1); fit a Gaussian mixed model with lmm(). glmm() takes a single response vector with unit prior weights — no aggregated-binomial (cbind(k,n-k)) response, prior weights or offset (finding G7, a scope limitation, fail-loud, documented).
- glmm() does not expose an is_singular flag or emit a boundary warning when a random-effect variance collapses to 0 (unlike lmm(), which added one at 4.5.0). The boundary MLE returned is correct and matches glmer's, but the diagnostic lme4's isSingular() provides is absent (finding G6, a gathered non-showstopper).
