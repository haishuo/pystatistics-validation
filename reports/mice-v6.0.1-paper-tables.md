# mice v6.0.1 — authoritative paper tables (ground truth)

Canonical **GPU-MICE benchmark numbers for pystatistics 6.0.1**, generated by
`drivers/mice/*` against a **PyPI-installed `pystatistics==6.0.1`**. The
`gpu-mice-paper` is a **downstream consumer**: it picks these up; it does not
produce them. Artifacts: `artifacts/mice/v6.0.1/runs/`.

- correctness: `mice_gate_v601.json` (MPS), `mice_gate_v601_cuda.json` (CUDA)
- fidelity vs R: `mice_compare_r_v601.json` (R mice 3.19.0)
- scaling/perf: `scaling_mps_v601.json`, `scaling_cuda_v601.json`

6.0.1 is the red-team fix release. On well-conditioned data the mice fixes are
inert; these numbers reproduce the 5.0.0/6.0.0 bless. **One behavior CHANGE is
material to this paper** — see §Behavior change (#10).

## Scaling — GPU vs CPU wall-clock (m=20, maxit=10, p=20, 3 repeats)

**Apple Metal (MPS):**

| n | CPU | GPU | speedup |
|---|---|---|---|
| 2,000 | 1.55s | 1.56s | 1.0× |
| 5,000 | 3.67s | 1.72s | 2.1× |
| 20,000 | 16.76s | 1.74s | **9.6×** |

**CUDA (RTX 5070 Ti, sm_120):**

| n | CPU | GPU fp32 | GPU fp64 | speedup (fp32) |
|---|---|---|---|---|
| 2,000 | ~1.3s | ~0.12s | 0.16s | ~11× |
| 5,000 | 3.08s | 0.12s | 0.30s | ~25× |
| 20,000 | 12.05s | 0.30s | 1.11s | **~40×** |

CPU scales ~linearly in n; the GPU stays roughly flat, so the speedup grows with n —
parity at n=2k, ~10× (Metal) / ~40× (CUDA) at n=20k. This is the headline GPU-MICE
result, freshly at 6.0.1.

## Behavior change (#10) — GPU categorical fits now fail loud

At 6.0.1 a **degenerate** GPU categorical/binary/ordinal fit (e.g. an extreme-scale
predictor that collapses the fp32 model) raises `ValidationError` ("GPU MICE
produced non-finite imputations…") instead of silently collapsing every imputed
cell onto level 0 (the 6.0.0 defect). CPU handles the same design and returns a full
category spread. **Any gpu-mice-paper claim about the GPU categorical path handling
degenerate/near-degenerate designs must be checked against this** — the GPU path now
refuses rather than returning wrong imputations. This is the reason the paper's
re-pin is NOT a mechanical version swap.
