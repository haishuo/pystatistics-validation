> This report validates **pystatistics mice v4.6.13**, installed from **pypi**. Evidence lives in `artifacts/mice/v4.6.13/`. It was generated by `render_report.py` from frozen artifacts — **do not edit numbers by hand**; fix the artifact or the renderer and re-render.

**Subsystem:** Multiple Imputation by Chained Equations (MICE) (`pystatistics.mice`)

## 1. What statistical procedure is implemented?

Multiple imputation of missing data by chained equations: each incomplete variable is imputed in turn from a regression on the others, cycling for several iterations to produce n_imputations completed datasets. Analyses are run on each completed dataset and combined by Rubin's rules, propagating imputation uncertainty into the final standard errors. Entry point: mice(data, *, seed, n_imputations=5, max_iter=5, method='pmm', backend='cpu'|'gpu'|'gpu_fp64'|'auto') -> MICESolution; pooling via pool(estimates, variances, dfcom=) -> PooledSolution.

## 2. Which algorithms are used?

- Chained equations: initialize missing cells by column mean, then for max_iter iterations visit each incomplete column and impute it from a model fit on the observed rows; repeat for n_imputations independent chains with separate RNG streams (seed mandatory).
- Per-column methods mirror R mice: pmm (predictive mean matching, default for numeric), norm (Bayesian linear regression), logreg (binary), polyreg (unordered categorical, via the multinomial module), polr (ordered, proportional-odds with a ridge penalty on slopes to stay stable under chained-equation separation).
- Inference by Rubin's rules: total variance T = Ubar + (1 + 1/m) B, Barnard-Rubin degrees of freedom, with relative increase in variance, lambda, and fraction of missing information reported.
- Backends: CPU (NumPy/SciPy, fp64, the R-validated reference path) and GPU (PyTorch, batched chains on CUDA/MPS). The GPU sweep is fp32, but the separation-prone DISCRETE fits (logreg/polyreg/polr) are computed in fp64 on CUDA/CPU (Metal keeps fp32) so single-precision cannot collapse an imputation onto one category; the numeric norm/pmm draw uses a ridged Gram with an end-of-sweep non-finite fail-loud guard. gpu_fp64 runs the whole sweep in fp64 on CUDA.

## 3. How does it compare to R mice?

The CRAN mice package (van Buuren & Groothuis-Oudshoorn, JSS 2011), the de-facto reference for chained-equation imputation. pystatistics mirrors its defaults (n_imputations=5, max_iter=5, pmm for numeric) and method names. Agreement is assessed by per-variable imputed-distribution distance (mean/quantile differences for numeric, Wasserstein for mixed types) rather than exact equality, since imputation is stochastic.

Also compared against: miceforest (LightGBM-based ML imputer) for large-scale speed.

## 4. What numerical tolerances are expected?

- **fidelity_vs_r:** Imputation is stochastic, so agreement is distributional, not exact: per-variable imputed means/quantiles (numeric) and 1-Wasserstein distance are compared and expected small. Measured at 4.6.13 on a mixed DGP (numeric/binary/ordered): |mean diff| <= 0.05 and W1 <= 0.05 across pmm/logreg/polr, matching R.
- **rubin_coverage:** Validity is judged by Monte-Carlo CI coverage of the analysis-model slopes: MICE recovers ~0.95 nominal coverage. Measured (40 reps, MCAR): cpu 0.955, gpu-fp32 0.935 (CUDA) / 0.945 (MPS), gpu_fp64 0.920 -- all at the target within Monte-Carlo error.
- **gpu_vs_cpu:** fp32 GPU imputations preserve Rubin coverage and pooled point estimates within the GPU/fp32 tolerance tier; the pooled mean SE matches the CPU path to ~2%. Large single-replication pooled-SE differences (up to ~30%) are RNG/Monte-Carlo noise in the between-imputation variance B (numpy vs torch streams), NOT fp32 bias -- proven because gpu_fp64 (fp64) shows the same single-rep spread vs cpu. MPS rejects fp64.

## 6. What are the known limitations?

- Assumes missing-at-random (MAR); MNAR requires auxiliary information the model does not include.
- GPU default is fp32 (fp64 only on CUDA via backend='gpu_fp64'); MPS has no fp64. The discrete fits are computed in fp64 on CUDA regardless, so separation cannot silently collapse an imputation.
- polr under chained equations can drive a column toward (quasi-)complete separation; a ridge penalty on slopes stabilizes it, but extreme designs remain hard.
- Fully-missing columns are rejected (unimputable); columns with no missing values are skipped.
- Categorical columns are handled as integer codes with tracked level maps; very high-cardinality nominal variables stress polyreg.
