# Validation report — pystatistics `timeseries` v4.8.0

> This report validates **pystatistics timeseries v4.8.0**, installed from **pypi**. Evidence lives in `artifacts/timeseries/v4.8.0/`. It was generated by `render_report.py` from frozen artifacts — **do not edit numbers by hand**; fix the artifact or the renderer and re-render.

**Subsystem:** Time series — diagnostics, stationarity, ARIMA, ETS, decomposition (timeseries) (`pystatistics.timeseries`)

## 1. What statistical procedure is implemented?

The timeseries module is the corpus's largest, and this is its first-time validation across the WHOLE public surface. It covers five sub-groups, each matched to its canonical R reference: DIAGNOSTICS — acf/pacf (autocorrelation and partial autocorrelation, stats::acf/pacf, lag-0 included in the correlation vector), diff (base::diff with lag/differences), ndiffs (number of differences for stationarity, forecast::ndiffs, default test kpss); STATIONARITY TESTS — adf_test (Augmented Dickey-Fuller unit-root test, tseries::adf.test, default regression 'ct' = constant+trend) and kpss_test (KPSS stationarity test, tseries::kpss.test, level/trend, lshort bandwidth); ARIMA — arima (stats::arima, methods CSS-ML default / ML / CSS / Whittle, seasonal (p,d,q)(P,D,Q)[m], include_mean), forecast_arima, auto_arima (Hyndman-Khandakar stepwise selection, forecast::auto.arima), and arima_batch (a batched Whittle fit over K series, with a CUDA GPU path); ETS — ets (exponential smoothing state-space models, forecast::ets, including 'Z' automatic model selection by AICc) and forecast_ets; DECOMPOSITION — stl (seasonal-trend decomposition by loess, stats::stl) and decompose (classical moving-average decomposition, stats::decompose). Every quantity is validated against R on identical float64 inputs, with statsmodels as an independent triangulation for stl and the ADF p-value. The module is CPU-first fp64; the only GPU path is arima_batch's batched Whittle likelihood (a spectral/periodogram computation, not a normal-equations Gram — the CF-1 fp32-Gram exposure does not apply).

## 2. Which algorithms are used?

- Diagnostics (deterministic, machine-precision vs R). acf/pacf follow stats::acf/pacf exactly: the biased (divide-by-n) autocovariance, lag-0 normalised to 1 and RETAINED in the returned vector, demeaning on by default; pacf via the Durbin-Levinson recursion. diff is base::diff (iterated lag-d differencing). ndiffs repeatedly differences and re-tests until the stationarity test stops rejecting or max_d is hit — default test='kpss' to match forecast::ndiffs (a pre-4.6.4 default of 'adf' was corrected; the two tests have OPPOSITE null hypotheses so the default matters).
- Stationarity tests. adf_test fits the ADF regression Δy_t = α + βt + γ y_{t-1} + Σ δ_i Δy_{t-i} (default regression='ct', matching tseries::adf.test which always includes constant+trend; 'nc'/'c'/'ct' selectable), lag order trunc((n-1)^(1/3)) as tseries, and reports the t-statistic on γ — exact vs tseries — with a MacKinnon (1994/1996) response-surface p-value (matches statsmodels adfuller; a pre-4.6.4 p-value that was wrong in the fail-to-reject region was corrected). kpss_test computes the KPSS statistic with a Bartlett long-run-variance estimate at the lshort=trunc(4*(n/100)^(1/4)) bandwidth (tseries default; lshort/llong selectable) for null='Level' or 'Trend', with the tseries interpolated-and-capped [0.01,0.99] p-value.
- ARIMA (exact ML / CSS-ML, optimizer-tier). arima maximises the Gaussian likelihood via a state-space Kalman filter (methods: CSS-ML default — CSS start then ML; ML; CSS; and Whittle spectral approximation), matching stats::arima's likelihood and mean/drift handling; L-BFGS-B optimisation. Seasonal models multiply the AR/MA polynomials (1-φB)(1-ΦB^m) etc. Information criteria (AIC/AICc/BIC) count the FREE estimated parameters (p+q+P+Q + mean-if-estimated + 1 for the innovation variance), matching stats::arima — a pre-4.6.4 defect counted the EXPANDED multiplicative-polynomial coefficients, silently inflating seasonal AIC and mis-driving auto_arima's seasonal selection. auto_arima runs the Hyndman-Khandakar stepwise search over (p,d,q)(P,D,Q) by AICc, matching forecast::auto.arima; forecast_arima produces point forecasts and prediction intervals from the state-space model. REGRESSION WITH ARIMA ERRORS (VA-4): arima(xreg=X) fits y = Xβ + η with η an ARIMA process, matching stats::arima(xreg=) — the regression coefficients are optimised jointly with the ARMA parameters on the differenced scale (diff(y − Xβ) = diff(y) − diff(X)β, differencing commutes with the linear regression), with joint-Hessian standard errors; include_drift adds a linear time-trend regressor (the models R reports 'with drift', so an ARIMA(p,1,q) 'with drift' is an ARMA-with-mean on the differenced series); fixed= holds named coefficients constant during estimation (stats::arima's parameter masking). auto_arima(allowdrift=True, default) selects drift models when d+D==1 and drift lowers the IC, like forecast::auto.arima; forecast_arima(newxreg=) forecasts by continuing the regression mean and drift. The exact-ML/CSS regression path is CPU-only (the Whittle/arima_batch GPU kernels carry no regression term; xreg/drift/fixed fail loud on method='Whittle').
- ETS (state-space exponential smoothing, optimizer-tier). ets fits the error/trend/season taxonomy (error A/M, trend N/A/Ad, season N/A/M) by maximising the Gaussian likelihood over smoothing parameters and initial states, matching forecast::ets for a specified model. Automatic selection via 'Z' wildcards ('ZZZ' default, matching forecast::ets) enumerates the admissible candidate models — multiplicative components only for strictly-positive data, unstable multiplicative-trend models excluded by default as in forecast::ets — and picks the minimum-AICc model, disclosing the selection. The reported log-likelihood is the FULL Gaussian log-likelihood (see tolerances — a documented convention difference from forecast::ets's concentrated form; selection is unaffected).
- Decomposition (deterministic given parameters). stl replicates stats::stl exactly (Cleveland, Cleveland, McRae & Terpenning 1990): the inner loop of cycle-subseries loess smoothing, the low-pass filter (two moving averages of length m, one of length 3, then a loess), seasonal = smoothed subseries minus low-pass, and a trend loess of the deseasonalised series; the outer robustness loop with bisquare weights when robust=True. Loess is R's q-nearest-neighbour tricube-weighted local polynomial with R's default degrees (s.degree=0, t.degree=1, l.degree=1) and window rules — a pre-4.6.3 'simplified' reimplementation leaked the trend into the seasonal on strongly-trending series and was rewritten. decompose is classical moving-average decomposition (stats::decompose, additive/multiplicative). CPU-only fp64.
- arima_batch (batched Whittle; the only GPU path). arima_batch fits K independent ARMA(p,q) models to the rows of a (K,n) matrix by the Whittle spectral (periodogram) approximation. backend='cpu' loops the single-series arima(method='Whittle') fitter in fp64; backend='gpu' runs one batched rFFT + one batched Adam optimisation in fp32; backend='gpu_fp64' the same in fp64 (CUDA-only). A host-side fp64 stationarity/invertibility gate (version-stable, R14) enforces one failure contract across all backends: if ALL series fail it raises ConvergenceError; if SOME fail their estimates are set to NaN with a loud warning; a non-stationary AR is NEVER returned as a plain number. Whittle is a spectral likelihood with no normal-equations Gram, so the CF-1 fp32-Gram silent-wrong pattern does not apply.

## 3. How does it compare to R stats/forecast/tseries?

Each function is validated against its canonical R reference on identical float64 inputs (each series is dumped from the central HDF5 store and read by both engines): acf/pacf/diff vs stats/base, ndiffs vs forecast::ndiffs, adf_test vs tseries::adf.test, kpss_test vs tseries::kpss.test, arima/forecast_arima vs stats::arima, auto_arima vs forecast::auto.arima, ets/forecast_ets vs forecast::ets, stl vs stats::stl, decompose vs stats::decompose. The reference METHOD is matched between engines (e.g. arima CSS-ML vs CSS-ML; ets model string vs the same string; adf regression 'ct' vs tseries' constant+trend) — never a different estimator. Agreement is an honest two-tier contract: deterministic quantities (acf/pacf, diff, the test statistics, stl/decompose) match to machine precision or the defined convention; MLE fits (arima, ets, auto_arima) match on log-likelihood and forecasts to an optimizer tier, with coefficients bounded by the optimizer. statsmodels (STL, adfuller) is used as an INDEPENDENT third reference where two engines are needed to adjudicate (it agreed with R stats::stl against the pre-4.6.3 stl, and with tseries on the ADF statistic while pinning the correct MacKinnon p-value).

Also compared against: statsmodels STL, statsmodels adfuller (MacKinnon p-values).

## 4. What numerical tolerances are expected?

- **g1_deterministic_tight:** Deterministic quantities match R to machine precision on identical inputs: acf and pacf max abs difference ~1e-16..1e-13 across all series; diff exact (0); classical decompose seasonal/trend/random ~1e-14; stl seasonal/trend/remainder ~1e-14..1e-13 vs stats::stl at matched windows/degrees (co2 seasonal 2.4e-14, trend 7.4e-13 — the pre-4.6.3 stl was silently wrong here, trend leaking into a range-82 'seasonal' vs the true ~6). These are exact-arithmetic agreements, not approximations.
- **g1_stationarity_tight_stat:** The ADF and KPSS test STATISTICS match tseries to machine precision at matched specification (ADF regression='ct' stat abs ~1e-14 on sim/nile/near-unit; KPSS stat abs ~1e-14 for Level and Trend at the matched lshort bandwidth). The ADF p-value is the MacKinnon (1994/1996) response surface and matches statsmodels adfuller to ~1e-4 across the full range including the fail-to-reject tail (near-unit-root p=0.9216 vs statsmodels 0.9216; tseries' coarse table gives 0.9144 there — the statistic is identical, tseries' table is the less accurate p-value). KPSS p-values use tseries' interpolated-and-capped [0.01,0.99] convention.
- **g1_mle_two_tier:** MLE fits are an honest two-tier contract with the method matched between engines. arima ML/CSS-ML on a known ARMA(1,1) DGP matches R to machine precision (loglik -576.5267 = R; ar/ma to ~1e-4); seasonal ARIMA (airline model) matches R on loglik AND on the now-correct AIC (free-parameter count k=3, not the pre-4.6.4 expanded-polynomial k=15). auto_arima's stepwise selection matches or beats forecast::auto.arima on AICc: seasonal (2,1,1)(0,1,0)[12] with AICc 1018.166 = forecast::auto.arima (order-identical); non-seasonal on AirPassengers reaches ARIMA(2,1,2)+drift at AICc 1355.17, a strictly LOWER value than R's (4,1,2)+drift (1357.22) because pystatistics' exact-ML optimizer finds an optimum forecast::Arima/stats::arima miss (see limitations — a robustness advantage, R-verified, not a divergence from R's estimator). ets parameters/states/fitted match forecast::ets for a specified model; 'ZZZ' selects the same natural models (MAM on AirPassengers). The optimizer tier: CSS and boundary/near-non-invertible cases (e.g. an over-fit (2,1,1) whose MA hits the unit circle) can land at a different local optimum than R — a stated contract, not a defect; pystatistics' SSE is never worse than R's.
- **g1_xreg_two_tier:** Regression with ARIMA errors (VA-4) matches stats::arima — the exact-ML reference (MLE sigma2; predict.Arima prediction SEs use that sigma2). On the reference fits the estimator-invariant quantities agree tightly: coefficients ~5e-6, log-likelihood ~1e-9, AIC/sigma2 machine-precision, standard errors ~4e-5 (an AR(1)+2-xreg model), with the joint (ARMA+regression) vcov matching R's var.coef. The RIGOR R10 hard cases all match: xreg under differencing d=1 (the β is identical whether one differences-then-regresses or regresses-then-differences), near-collinear xreg (the poorly-identified pair recovers R's optimum), all-but-one fixed (a fixed coefficient is pinned EXACTLY, carrying zero variance, excluded from the IC free-parameter count as in R), drift under d=1 (the trend becomes the differenced-series mean), and seasonal+xreg (sar1 and β jointly recovered to machine precision). forecast_arima(newxreg=) point forecasts and prediction SEs match predict.Arima to ~1e-6 (drift forecasts continue the trend; xreg forecasts add the future regression mean). auto_arima(allowdrift=True) selects the same drift models forecast::auto.arima does (a random-walk-with-drift -> (0,1,0) with drift; the seasonal AirPassengers selection is UNCHANGED because its d+D==2 excludes drift). fail-loud (Guarantee 2): xreg row-count mismatch, unknown fixed name, all-coefficients-fixed, drift under d+D>=2, method='Whittle' with a regressor, init with xreg, and missing/misshaped newxreg all raise ValidationError.
- **g2_fidelity_fail_loud:** Fail-loud, no silent substitution (RIGOR A6 / G2): 12/12 fail-loud checks pass. Invalid ETS model strings, multiplicative ETS on non-positive data, negative/over-parameterised ARIMA orders, invalid adf/kpss regression, stl period<2 or series shorter than two periods, and invalid ndiffs test all raise ValidationError/ConvergenceError. Non-finite (NA) input raises rather than being silently skipped — a DELIBERATE, documented divergence from R (stats::acf's na.action, stats::arima's Kalman NA-skipping): pystatistics refuses non-finite input; impute or drop NAs first.
- **g3_performance_cpu:** CPU vs R across series length (Guarantee 3, same estimator): all four timed functions are at or FASTER than R at every size — acf 0.14x at n=20000, arima 0.41x at n=5000, stl 0.35x at n=4800, and ets 0.43x at n=5000 — with empirical complexity matching R (no complexity-class gap). ets was the last gap: at 4.6.5 it was ~3-11x SLOWER (10.7x at n=5000) because its state-space recursion ran in interpreted Python versus R's compiled C. 4.6.6 JIT-compiled the recursion with numba (@njit(cache=True, fastmath=False), matching the module's existing ARIMA-Kalman and STL kernels — numba is already a required dependency), flipping ets from 10.7x slower to 0.43x and flattening the py/R slope from 1.09 to 0.39 (the growing-with-n gap is gone). fastmath=False forbids float reassociation, so the JIT path reproduces the numpy path BIT-FOR-BIT: ETS estimates are UNCHANGED from 4.6.5 (max abs difference 0.0 across every reported field — an R6 optimize-and-re-validate cycle, not a new fit).
- **arima_batch_contract:** arima_batch honors ONE fail-loud failure contract across all backends (host-side fp64 gate, version-stable R14): a healthy batch returns all-converged with no warning; a partial-failure batch sets the failed rows' estimates to NaN and emits a loud warning naming the count (never a non-stationary AR as a plain number); an all-failure batch raises ConvergenceError; single-series arima(Whittle) raises. The CPU batch equals the single-series arima(Whittle) loop EXACTLY at matched tolerance (0.0); at default tolerances they differ by ~1e-6, the batch's looser default gradient tol (1e-5) vs arima's 1e-8.
- **gpu_whittle_g3_corollary:** The arima_batch GPU path (CUDA, RTX 5070 Ti, torch 2.11+cu128) meets the Guarantee-3 GPU corollary: it beats the CPU beyond K~500, reaching 7.6x (fp32) / 6.0x (fp64) over the fp64 CPU at K=2000,n=1000 (a fixed ~200ms dispatch overhead makes it slower for small K — expected). The fp32-vs-fp64 accuracy pivot (R11) is decisive: fp32_ar_rel == fp64_ar_rel at EVERY K, so the gap versus exact ML is the Adam(GPU)-vs-L-BFGS-B(CPU) OPTIMIZER, not precision (sigma^2 recovered to ~1e-6 either way). No silent-wrong: on near-unit-root/near-non-invertible fp32 batches the host-side gate NaN-masks or raises exactly as on CPU (R12/R13 re-proven on CUDA). CF-1 does not apply (spectral likelihood, no Gram).

## 6. What are the known limitations?

- The ets log-likelihood and AIC use the FULL Gaussian convention; forecast::ets reports Hyndman's concentrated pseudo-likelihood -0.5*n*log(SSE). The two differ by the exact deterministic constant 0.5*n*[log(n/2π)-1] (verified: nile n=100 -> 88.36; a sim n=300 -> 429.9). The number of parameters is identical, so AICc RANKING — and therefore 'ZZZ' model selection — is unaffected; only the printed log-lik/AIC value differs from forecast::ets. Documented, not silent.
- The ADF p-value is the MacKinnon (1994/1996) response surface (matching statsmodels adfuller), NOT tseries' coarse Dickey-Fuller table interpolation. The ADF STATISTIC matches tseries exactly; the p-values agree closely except in the deep tails where tseries interpolates/caps a sparse table (near-unit-root: pystatistics/statsmodels ~0.92, tseries 0.91). MacKinnon is the more accurate method and the reason a user comparing printed p-values to tseries::adf.test will see small differences.
- ndiffs(test='adf') can differ from forecast::ndiffs by one on a borderline series (Nile: pystatistics 1 vs R 0) because the ADF p at d=0 sits essentially on α=0.05 (0.0561) and the MacKinnon-vs-tseries p-value convention tips the decision. The DEFAULT test='kpss' matches forecast::ndiffs everywhere; this is a documented, bounded boundary case on the non-default path.
- Non-finite (NA) input to any timeseries function raises rather than being silently handled — a deliberate fail-loud divergence from R (stats::acf's na.action=na.pass, stats::arima's Kalman NA-skipping). Impute or drop NAs before calling. This is a fidelity choice (Guarantee 2), not a missing capability.
- Prediction intervals for regression-with-ARIMA-errors models (and all arima forecasts) use the MLE innovation variance sigma2 = SSR/n — the value stats::arima reports and predict.Arima uses, which pystatistics matches to ~1e-6. forecast::Arima instead reports a degrees-of-freedom-adjusted sigma2 = SSR/(n - ncoef) and therefore slightly WIDER intervals (the factor sqrt(n/(n-ncoef))). This is a documented convention difference, consistent with the rest of the module (pystatistics reports the MLE sigma2 everywhere); the point forecasts and the regression/ARMA coefficients are identical to both R paths. A user comparing printed intervals to forecast::Arima will see them a touch narrower.
- The regression-with-ARIMA-errors path (xreg / include_drift / fixed) is CPU-only, by construction: the joint ARMA+regression likelihood is the sequential Kalman filter with no amortisable batched FLOPs, exactly like the base exact-ML arima path (the only ARIMA GPU path is arima_batch's batched Whittle spectral likelihood, which carries no regression term). xreg/drift/fixed with method='Whittle' or an explicit GPU backend fail loud rather than silently computing a different problem (Guarantee 2). This matches all prior art — stats::arima and forecast::Arima are CPU-only for regression with ARIMA errors.
- arima_batch is Whittle-only and non-seasonal (the batched Kalman/CSS-ML paths are not implemented); it fails loud on unsupported specs. The Whittle estimator is an O(1/n) spectral approximation to exact ML, so batch coefficients differ from an exact stats::arima ML fit by the approximation floor on short series — documented, and the single-series exact paths (CSS-ML/ML) remain available.
- The arima_batch GPU path exists ONLY because the batched Whittle likelihood (one rFFT + elementwise spectral reductions over K series) is a genuine GPU workload that beats the CPU beyond K~500. It is fp32 (or fp64 on CUDA) Adam optimisation whose estimates differ from exact ML by the optimizer (identically in fp32 and fp64 — not a precision effect); it is never silently wrong (host-side fp64 stationarity gate). For small K or single series the CPU/exact paths are the right choice.
- auto_arima is a stepwise heuristic (like forecast::auto.arima) and does not guarantee the global AICc minimum, so it can terminate on a DIFFERENT order than R's auto.arima. On AirPassengers (non-seasonal) pystatistics selects ARIMA(2,1,2)+drift at AICc 1355.17, a STRICTLY LOWER (better) value than forecast::auto.arima's ARIMA(4,1,2)+drift at 1357.22 — because pystatistics' exact-ML optimizer reaches the (2,1,2)+drift optimum (loglik -671.27) that forecast::Arima and stats::arima both miss (they stall at a local optimum, loglik -681.06 from their default starting values). pystatistics' likelihood at that optimum was confirmed by evaluating its exact coefficients under R's own likelihood (R returns the identical loglik/sigma2), and the (2,1,2) fit is causal and invertible. The ARIMA MLE estimator itself matches R for any FIXED order (AICc bit-identical on the matched (4,1,2)+drift model); only the stepwise search endpoint differs, and pystatistics' endpoint is never worse on the AICc criterion auto.arima itself optimizes. This is a robustness advantage of the optimizer, not a divergence from R's estimator — documented so a reviewer expecting order-identical auto.arima output understands why the orders can differ.
