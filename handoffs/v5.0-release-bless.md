# pystatistics 5.0.0 — whole-library bless (carry-forward) note

**Date:** 2026-07-12. **Prepared, not yet published** (awaiting user publish go +
OPERATIONS #6).

## Verdict

> **5.0.0 is BLESSABLE. It is a rename-only consistency cut over the already-blessed
> 4.8.1 line — zero statistical change — so the whole-library bless carries forward.**

## Basis

- **What 5.0 is:** the single pre-launch API-consistency sweep. Breaking renames
  of parameters, option values, and result accessors across the whole corpus; two
  scheduled deprecations cleared; internal `*Params` payloads unexported. The full
  list is the CONVENTIONS.md "5.0 migration table" and CHANGELOG 5.0.0. **No
  estimator, backend, precision, algorithm, or numeric output changed.**
- **Bless precondition (VA-2/VA-3):** CLEARED prior to this cut — the gam
  `s(x, by=)` / `nb()` validation session closed clean and shipped 4.8.1 (see
  `handoffs/va2-va3-gam-validation.md`). Nothing rests in "documented" that is
  fixable. The corpus was fully blessed at 4.8.1.
- **No-drift evidence:** the library's own R-anchored test suite (which pins CPU
  results to R fixtures at rtol≈1e-10 across all 9 corpus modules + survival/
  timeseries/gam extensions) passes at the 5.0 HEAD unchanged: **3794 passed, 109
  skipped, 27 deselected** — the identical pass count to the pre-rename 4.8.1
  baseline. A rename that altered a number would have broken an R-fixture test.
- **Per-module renames were each independently verified** (module tests green +
  residual-spelling greps) before commit; a full-suite checkpoint was run after
  the cross-cutting family-name commit and again after the export prune.

## Why the reports were not re-rendered at 5.0

The frozen validation artifacts and rendered reports (`reports/{module}-v4.8.*.md`)
validate **statistical behavior**, which 5.0 does not touch. Re-running R fixtures
for a pure rename would reproduce the same numbers against the same references at a
new version string. The blessed evidence is the 4.8.1 corpus; 5.0 inherits it by
the no-drift argument above. If a downstream consumer needs artifacts stamped 5.0,
re-render is mechanical (same drivers, new version) and adds no new numeric claim.

## Accepted-limitations appendix (B)

The deliberate carve-outs from R parity are unchanged by 5.0 and are recorded in
`pystatistics/CONVENTIONS.md` → "Capability scope — deliberate carve-outs"
(gam exotic bases re/ds/gp/fs; regression non-treatment contrasts and general
`quasi()`; survival `exact` ties; montecarlo `h`/`hinv`/antithetic/blocked;
multivariate `prcomp` `tol` truncation). 5.0 additionally records, in CONVENTIONS
amendment A14, the reference-package vocabulary kept by exemption (mice mipo
`riv`/`lambda_`/`fmi`/`df`, ETS letter codes, montecarlo `.t`/`.t0`, the `'nb'`
family shorthand).
