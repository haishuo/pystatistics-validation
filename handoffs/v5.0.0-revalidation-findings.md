## Findings

### F1 — ordinal `polr` gained `cauchit` + `loglog` links since 4.6.10 (unvalidated)
The 4.6.10 report/meta documented `cauchit`/`loglog` as fail-loud ("Unknown link").
5.0.0's `polr` implements both. This is a functional addition (not a 5.0 rename) that
was never validated. Surfaced because the fidelity suite's fail-loud negative checks
for these two links now no-raise (11/13 vs 13/13).

### F2 — `cauchit` polr link is silently wrong vs MASS::polr (probable SHOWSTOPPER-class)
VERIFIED by direct head-to-head on identical synthetic data (seed 7, n=400, 3 cats):
- py `polr(link='cauchit')`: loglik −357.884698, coef [1.36932, −0.86220]
- R `MASS::polr(method='cauchit')`: loglik −360.448312, coef [1.35065, −0.85030]
- Δloglik ≈ 2.56 here; the ordinal agent saw 6–11 on MASS::housing. Coef 1–2% off.
- Both `converged=True`, no R warnings ⇒ not a convergence artifact; the engines are
  optimizing different cauchit objectives. The link math (`g⁻¹(η)=½+arctan(η)/π`) is
  the standard Cauchy CDF and matches the code's own comment, so the defect is in the
  cauchit **fit path** (gradient/loglik), not the link definition.
- `logit`/`probit`/`cloglog` match R to ~1e-11 (optimizer tier); `loglog` matches
  (~3.8e-6 coef, 3.6e-9 loglik — clean). Only `cauchit` disagrees materially.
- **Character:** a user calling `polr(link='cauchit')` gets a wrong fit, converged,
  no warning — quiet-wrong (RIGOR R16 territory). Mitigant: cauchit is a rarely-used,
  non-default link (default is logit); and this predates 5.0 (latent, not a 5.0
  regression). Disposition (R16 "user decides"): bundle a fix into 5.0.1 vs hotfix now.

Everything else in ordinal/multinomial reproduced 4.6.10 exactly (logit/probit/cloglog
polr ~1e-11, multinom ~1e-12, predict exact, separation fail-loud, CPU perf, GPU CF-1
MPS no-neg-var). The rename adaptation itself is sound. Ordinal artifacts left
UN-manifested (no bless) pending resolution.

### F2 RESOLUTION (2026-07-13) — py's cauchit is CORRECT; MASS::polr is the outlier
Root-caused with an independent optimizer. On the seed-7 dataset:
- **Independent scipy cauchit MLE** (Nelder-Mead, neutral start): loglik
  −357.884698, coef [1.36933, −0.86221], thr [−0.63149, 1.70865].
- **pystatistics `polr(link='cauchit')`**: loglik −357.884698, coef
  [1.36932, −0.86220] — **matches the independent MLE to ~1e-5.**
- **MASS::polr cauchit**: loglik −360.448312 — a *worse* optimum, and its
  reported loglik doesn't even match the standard cauchit likelihood at its own
  coefficients (−357.89). `polr`'s cauchit under-converges on heavy tails (a
  known MASS weakness).

**Verdict: no library defect, no silent-wrong, no showstopper, NO 5.0.1.** py
computes and optimizes the standard cauchit cumulative-link likelihood correctly.
The finding reduces to: `cauchit`+`loglog` were added after 4.6.10 and never
validated, and the ordinal validation artifacts still call them fail-loud.
